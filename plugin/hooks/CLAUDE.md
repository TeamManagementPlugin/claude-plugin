# Hooks Module CLAUDE.md

## Purpose
Provides behavioral enforcement, state management, and integration hooks for team-management with multi-provider issue tracking synchronization capabilities (GitLab, Jira, GitHub / Gitea). This module is the **single source of truth** for provider utilities, imported by both hooks and MCP server.

## Narrative Summary

The hooks module serves as the enforcement and integration layer for team-management, implementing the core DAIC (Discussion-Alignment-Implementation-Check) methodology through Python hooks that cannot be bypassed. It manages session state, enforces workflow patterns, and provides automatic integration with external systems like GitLab.

The module operates through Claude Code's hook system, intercepting tool usage, user messages, and session events to enforce behavioral patterns and maintain system state. With the addition of multi-provider issue tracking integration, it now provides seamless synchronization between Claude tasks and external issue tracking systems (GitLab, Jira).

**Architecture Note**: This module is the canonical location for provider utilities (gitlab_utils.py, jira_utils.py, shared_state.py). The MCP server imports these utilities directly from .claude/hooks/ to avoid file duplication and ensure consistency.

## Module Structure

### Core Hook Files
- `__init__.py` - Docstring-only package marker; makes `plugin.hooks` importable as a package for the dev-tooling test suite. At runtime hook modules are loaded flat from the plugin install via `_shim.py` and import each other top-level (e.g. `import shared_state`)
- `sessions-enforce.py` - DAIC enforcement and branch protection
- `session-start.py` - Automatic task context loading on session start
- `user-messages.py` - Read-only task/protocol hints, context/token monitoring, de-noised protocol-suggestion detection, and whole-word emergency STOP/SILENCE (no trigger-phrase mode switching — DAIC mode is engine/MCP-driven). The emergency-stop and detection matchers live in `shared_state.is_emergency_stop` / `detect_protocol_intent` (pure, unit-testable — user-messages.py `json.load(sys.stdin)`s at import and can't be imported by a test). **Behavioral coverage** (m-test-hook-and-mcp-coverage-gaps): the module-level flow (auto-compact trigger + once-per-session suppression, 80%/90% token warnings, post-compact restoration + `compact-pending.flag` consumption, workflow-bypass short-circuit, no-task branch hint) is exercised end-to-end by `test/test_user_messages_hook.py`, which subprocess-drives the hook with stdin payloads over a temp project (the `CLAUDE_PLUGIN_ROOT`-scrubbed subprocess harness — the only way to test a hook that consumes stdin at import); malformed-stdin/depth-reset stay in `test/test_hook_stdin_guards.py`
- `post-tool-use.py` - Protocol end-condition injection, multi-provider auto-sync, auto-compact token monitoring, and auto-worklog appends. **Subagent-depth decrement guard** recognises BOTH dispatch tool names — `tool_name in ("Task", "Agent")` — to mirror the `task-transcript-link.py` increment guard (some harnesses name the dispatch tool `Agent`). The auto-compact significant-tool set also includes `"Agent"` alongside `Task`/`Edit`/`Write`/`MultiEdit`. **Locked throttle counters** (m-hooks-hygiene-sweep, R2-6): all three counters (auto-compact, protocol-end-condition, auto-worklog) go through `shared_state.increment_counter_file` / `reset_counter_file` — concurrent PostToolUse hooks no longer lose-update each other with bare read_text/write_text. The end-condition throttle is increment-first: inject when `(counter - 1) % 10 == 0` (same observable cadence — first call after the engine deletes the counter file, then every 10th). The Jira auto-sync branch was simplified to the GitLab pattern: `get_jira_sync()` + early return on None (the hasattr-after-import probe and `JiraTaskSync()` re-instantiation fallback are gone).
- `pre-compact.py` - PreCompact hook for state preservation before context compaction (saves checkpoint, clears warning flags). **Entrypoint robustness** (m-enforcement-and-git-hardening): `json.load(sys.stdin)` is guarded (empty/malformed/non-dict → `{}`) and the protocol status line `isinstance`-guards a non-int `current_step` (`.get` + type check, no `KeyError`/`TypeError`) — the harness treats ANY non-zero PreCompact exit as a hook failure that errors out `/compact`, so these must never raise. Tests: `test/test_precompact_robustness.py`.
- `shared_state.py` - Cross-hook state management and utilities
- `task-transcript-link.py` - Task-transcript relationship management. Stages parent-transcript chunks into `.claude/state/{subagent_type}/{key}/` keyed per Task invocation (`subagent_type` from the hook's own `tool_input` via `shared_state.subagent_dir_name`; `{key}` = `shared_state.subagent_transcript_key(tool_input)`, identical in Pre/Post payloads). `post-tool-use.py` archives that keyed dir then `rmtree`s it. Per-invocation keying isolates parallel same-type subagents. **Bounded staging read** (m-fix-unbounded-transcript-reads): the parent transcript is read via `shared_state._read_file_tail(transcript_path, TRANSCRIPT_STAGE_CAP_BYTES, return_capped=True)` — bounded to the last 1 MB so this blocking hook's tiktoken-encode + RSS stay flat w.r.t. session length (the JSONL grows to tens of MB). The pre-work-removal strip loop runs only when the read was NOT `capped`: on a capped read the `Edit`/`Write`/`MultiEdit` work-start marker may sit BEFORE the window, so running the loop would pop every in-window entry and starve the subagent — retaining the bounded tail verbatim over-includes but never starves. The `_read_file_tail` / `TRANSCRIPT_STAGE_CAP_BYTES` import is hoisted ABOVE the subagent-depth increment so an `ImportError` fails before the increment (exit 1, non-blocking) instead of inside the post-increment `exit 2` block; an unreadable `transcript_path` degrades to empty staging + `exit 0` (`_read_file_tail` swallows read errors to `([], False)`) rather than wrongly blocking the Task. Test: `test/test_transcript_stage_cap.py`. **Subagent-depth increment guard** recognises BOTH dispatch tool names — `if tool_name not in ("Task", "Agent")` — because some Claude Code harnesses name the subagent-dispatch tool `Agent` instead of `Task` (the matching PostToolUse decrement in `post-tool-use.py` uses `tool_name in ("Task", "Agent")`, and the PreToolUse matcher in `hooks.json` is `Task|Agent`). When only `Task` was recognised, an `Agent` dispatch never incremented the counter, so `in_subagent_context()` always returned False inside such subagents — silently defeating the auto-worklog gate, the DAIC subagent bypass, reminder/auto-sync suppression, and transcript staging. **Per-line JSONL guard on the transcript read** (m-hooks-hygiene-sweep, C3): blank or unparseable lines are skipped instead of crashing the list-comprehension read — a crash here would land AFTER the subagent-depth increment, desyncing the counter until the next turn-boundary reset (same skip-and-continue pattern as shared_state.py's transcript readers). **Encoding + exception-safety around the increment** (h-fix-discard-clean-and-windows-transcript): the two transcript-chunk writes now use `.open('w', encoding='utf-8')` (they previously omitted encoding and crashed on Windows cp1252 with a non-ASCII transcript char), and the ENTIRE post-increment body is wrapped in `try/except Exception` — on any failure it decrements (undoing its own increment via the `did_increment` flag) and `sys.exit(2)` to BLOCK the Task. Blocking is load-bearing: a blocked Task means `post-tool-use.py` never runs its matching decrement, so the counter can't be double-decremented (a plain decrement + `exit 0` would let the Task proceed and get decremented a second time, corrupting a parallel sibling). `except Exception` (NOT `BaseException`) deliberately lets the normal `sys.exit(0)` early-returns (SystemExit) pass through, keeping the increment when the Task proceeds. Test: `test/test_task_transcript_link_depth.py`.
- `_shim.py` (h-hook-port-boot-detector; hardened m-enforcement-and-git-hardening) - Stdlib hook launcher invoked by `hooks.json` as `<python> _shim.py <hook-filename> [args]`. Picks the venv python under `${CLAUDE_PLUGIN_DATA}/venv` if present, else `sys.executable`, else a system python (Windows `python`/`py` — no `python3`), then hands off via `os.execv` (POSIX) / `subprocess.run`+`sys.exit(rc)` (Windows) with stdin and exit code intact. Pure stdlib — runs before the venv exists. **Missing-hook fail-open**: if the resolved hook file does not exist (a typo/rename in hooks.json), the shim writes a clear `[_shim] hook file not found: … — check hooks.json` to stderr and `sys.exit(0)` **before** the exec handoff — never exit 2, which on PreToolUse would hard-block every matching tool with a cryptic "can't open file" message. A manifest typo is a config error, not a policy verdict.
- `boot_detector.py` (h-hook-port-boot-detector) - `detect_legacy_install(project_root)` returns `{"signals": [...]}` only when a legacy `.claude/hooks/` script dir (the anchor) coexists with a corroborating signal (legacy hook entries in `.claude/settings.json` OR a duplicate `team-management` MCP registration in `.mcp.json`/settings.json); else `None`. Project-scoped (never inspects `~/.claude`). Consumed by the SessionStart advisory (`session-start.py`) and the PreToolUse companion (`sessions-enforce.py`). Pure stdlib + `hook_utils`.

#### Fail-Open Hardening (h-fix-daic-enforcement-fail-open)
PreToolUse contract: **only exit code 2 blocks a tool call**; any uncaught Python exception exits 1 (non-blocking) and SILENTLY disables DAIC / protected-path / frozen-path / branch enforcement for that call. The hook now enforces a **hybrid** failure model (documented in the module docstring at the top of `sessions-enforce.py`):
- **Foreseeable corruption fails CLOSED** via restrictive reader defaults — the state readers degrade instead of raising: `shared_state.check_daic_mode_raw` → `"discussion"` (blocks edits), `check_workflow_bypass` → `False` (not bypassed), `get_task_state` → null-task (branch fail-safe blocks edits), and local `load_config` → `DEFAULT_CONFIG` (keeps `blocked_tools` + branch enforcement live). The three `shared_state` readers moved `ensure_state_dir()` INSIDE the `try`, added an `isinstance(data, dict)` guard (valid-but-non-dict JSON no longer crashes a later `.get()`), and widened the `except` to `(FileNotFoundError, json.JSONDecodeError, ValueError, OSError)` — mirroring the already-safe `read_subagent_depth` pattern. `_load_frozen_paths` and the branch-check `subprocess.run` handler were widened the same way (`ValueError` / `OSError`), keeping their pre-existing degrade-to-`[]` / warn-and-proceed behaviour.
- **Unforeseen bugs fail OPEN, LOUDLY.** The whole executable flow now runs inside `def main()`; a bottom `if __name__ == "__main__": try: main() except Exception as exc: <stderr breadcrumb>; sys.exit(0)` backstop catches any residual exception. **exit 2 was deliberately rejected** for the backstop — the PreToolUse matcher also covers `Read|Grep|Bash`, so a blocking backstop would brick the whole session with no way to even diagnose. `except Exception` (NOT `BaseException`) lets every deliberate `sys.exit(2)` verdict — token-bridge secret guard, protected/frozen-path, DAIC, branch — raise `SystemExit` straight through, so the fail-closed guards are NOT weakened. All helper defs + `PROTECTED_PATHS` / `BASH_WRITE_PATTERNS` / `_BASH_WRITE_TARGET_RULES` stay module-level. Side effect: with the stdin parse now inside `main()`, the module no longer runs `json.load(sys.stdin)` at import (it is importable, though a plain `import` still needs `importlib` for the hyphenated filename). Sibling hooks `post-tool-use.py` + `user-messages.py` got the same canonical `pre-compact.py` stdin guard (only the stdin line in post-tool-use — the `_state_lock` hot-path is the separate `m-fix-posttooluse-lock-failure-resilience` task, below). #### Lock-Failure Resilience (m-fix-posttooluse-lock-failure-resilience)
The `_state_lock()` **acquisition** (`open('.claude/state/current_task.lock','a+')` + `flock`/`msvcrt.locking`) can raise `OSError` on a flock-less FS (network/synced drive), on permissions/ownership issues, or on `msvcrt` contention. On such a host, `post-tool-use.py`'s unguarded end-condition throttle call (`increment_counter_file`) re-raised and killed the PostToolUse hook (exit 1, no message) on **every** Bash call; `sessions-enforce.py` (PreToolUse) takes no lock, which matched the observed PostToolUse-only asymmetry. The fix distinguishes **best-effort** consumers (degrade) from **integrity** writers (fail-closed):
- **Best-effort consumers degrade** (`shared_state.py`). `increment_counter_file` / `reset_counter_file` and the subagent-depth helpers (`increment_subagent_depth` / `decrement_subagent_depth` / `reset_subagent_depth`, via the new `_mutate_subagent_depth(new_depth_fn)`) run under an **`entered` sentinel** — set as the LAST statement in the lock body so `entered is True` guarantees the result is bound. Three OSError paths: acquisition failure (`entered` False) → single UNLOCKED best-effort write (the FS is writable but flock-less, so the unlocked write succeeds); locked-write failure → swallowed in place (best-effort, `_state_lock` already `mkdir`s STATE_DIR so it is a genuine I/O error the unlocked retry cannot fix); release/close failure after the write (`_state_lock`'s `f.close()` is outside its inner try) → return the already-persisted value WITHOUT re-running (no double-increment / no stale-overwrite). Counter read-inc-write bodies are factored into `_increment_counter_unlocked` / `_reset_counter_unlocked` (internally swallow their own write `OSError`).
- **Integrity writers stay fail-closed.** `set_daic_mode` / `set_task_state` / `set_protocol_state` / `edit_state` are UNCHANGED — they keep raising on a lock failure (protected state must never fail-open). `test_integrity_writers_still_raise_on_lock_failure` locks this in.
- **Defense-in-depth block guard.** `post-tool-use.py`'s end-condition throttle block is now wrapped in `try/except Exception: pass`, matching the sibling auto-compact / worklog blocks (any residual failure → "no injection this call").
- **Two adjacent call sites use `shared_state.ensure_discussion_mode_best_effort()`** (near `set_daic_mode`) instead of a bare `set_daic_mode` — `session-start.py`'s no-protocol discussion fallback (reached on EVERY no-protocol session start) and `user-messages.py`'s emergency STOP. ## Configuration

### Hook Registration
Hooks are registered declaratively by the plugin manifest `plugin/hooks/hooks.json`, which Claude Code reads automatically when the plugin loads. Each entry invokes the stdlib launcher shim: `python3 ${CLAUDE_PLUGIN_ROOT}/hooks/_shim.py <hook-filename>`. No installer writes hook entries into `.claude/settings.json` anymore (the pip-era `installer/core.py::_register_hooks` was removed in m-installer-retirement).

1. Check for subagent context to avoid duplicate reminders
2. Detect implementation tool usage

5. **Provider-Aware Error Handling**: Handle sync errors gracefully with provider-specific fallbacks

### User Message Processing (user-messages.py)
1. Reset the subagent-depth counter at the turn boundary; short-circuit under workflow bypass
2. Inject read-only context: post-compact restoration, token/compact warnings, task/protocol hints
3. Detect protocol-suggestion phrases and remind to start a protocol (explain-and-ask; never runs the protocol itself)
4. Auto-save the user's message as a protocol note during the investigation step
5. Emergency STOP/SILENCE forces global discussion mode (transient — until session restart)

### Session Start (session-start.py)
1. Load current task context
2. Restore session state
3. Clear auto-compact flags (auto-compact-triggered.flag, compact-pending.flag) for fresh session
4. Provide task status and next steps
5. **Multi-Provider Initialization**: Initialize sync state for active provider (GitLab, Jira) if enabled

### PreCompact (pre-compact.py)
1. Read current task, branch, protocol state, and DAIC mode
2. Write checkpoint to `.claude/state/compact-pending.flag`
3. Clear context warning flags (global and task-scoped) so they can re-trigger
4. Clear auto-compact-triggered flag for re-monitoring after compaction
5. Show status message to user via stderr
6. **Exit 0 (not 2).** `PreCompact` has no blocking semantics — the exit-code-2 table in `knowledge/claude-code/hooks-reference.md` lists it as "N/A, shows stderr to user only", and the harness treats any non-zero PreCompact exit as a hook failure that errors out `/compact`. The checkpoint write and flag-clearing complete before the exit, so exit 0 is the correct success signal; the stderr status line is informational only. Regression-guarded by `test/test_protocol_engine_spike.py::TestSpikePreCompactSubprocess` (exact-match `returncode == 0`).

## Recent Bug Fixes and Improvements

### GitHub/GitLab Provider Crash, Pagination, and Token Redaction (h-fix-github-provider-crash-and-pagination)

**Branch**: `fix/github-provider-crash-and-pagination`. Four fixes in the provider utilities plus a shared base-class helper:

1. **Token redaction (cross-provider)**: New `IssueTrackingProvider._redact_token(self, text)` in `issue_provider_base.py` — single source of truth replacing `self.api_token` with `[REDACTED]`. Called in all three `_make_request` HTTPError handlers (`gitlab/api.py`, `github/api.py`, `jira_utils.py`) as `self._redact_token(e.response.text)[:500]` — redaction runs BEFORE the 500-char truncation so a boundary-split token can't leak.
2. **C1 crash fix**: `github/pr_manager.py::find_pull_request_by_branch` and `gitlab/mr_manager.py::find_merge_request_by_branch` now guard `isinstance(result, dict)` before `.get('error')`. Previously crashed with `AttributeError` when the list endpoint returned a non-empty list (PRs/MRs exist) — a list has no `.get`.
3. **Pagination discipline**: `gitlab/mr_manager.py::get_mr_notes` and `github/api.py::_get_label_name_to_id_map` now loop pages with `per_page=100` until a short page; the two branch-finders request `per_page=100`. Prevents silently missing notes/labels/PRs beyond the first page.
4. **M10 title guard**: `github/api.py::update_issue` changed its title guard from `if title:` to `if title is not None:`, so an intentional empty-string title is no longer dropped.

**Test coverage**: `test/test_provider_crash_pagination.py` (10 tests).

### Code Review Extraction Fix (v0.6.x - fix/code-review-extraction)

**Problem**: The `_extract_code_review_results()` method in `issue_provider_base.py` was only extracting code review titles instead of full review content when posting to MR/PR comments.

**Root Cause**: The regex pattern `r'# Code Review:.*'` was not capturing content beyond the title line because it lacked the `re.DOTALL` flag and proper continuation pattern.

**Fix Applied**:

#### issue_provider_base.py (lines 529-576)
1. **Enhanced Regex Pattern** (line 555): Changed from `r'# Code Review:.*'` to `r'# Code Review:.*?(?=\n#[^#]|\Z)'`
   - Captures full review content from title through all subsections
   - Uses non-greedy match (`.*?`) to prevent over-matching
   - Stops at next major section (single `#`) or end of file (`\Z`)
   - Uses `re.DOTALL` flag to match across multiple lines
2. **Input Size Limit** (lines 549-551): Added 1MB limit to prevent ReDoS attacks on large task files
3. **Match Iteration** (line 556): Uses `re.finditer()` to find all code review sections
4. **Last Review Selection** (line 562): Extracts the final passing review after any fixes

**Impact**:
- MR/PR comments now include complete code review results (Summary, Critical Issues, Warnings, Notes)
- Code review documentation is properly preserved in merge/pull request history
- All providers (GitLab, GitHub, Gitea) benefit from this shared utility fix
- Security improvement with input size validation

**Affected Providers**:
- GitLab: Merge request comments with full code review content
- GitHub: Pull request comments with full code review content
- Gitea: Pull request comments with full code review content (via GitHub-compatible API)
